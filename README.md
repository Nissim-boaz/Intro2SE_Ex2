# Moodle+

אתר קורסים למטלה 2 בקורס מבוא להנדסת תוכנה. לכל קורס יש עמוד עם תכנים, דגימת נוכחות בכיתה, הקלטות שיעור עם סיכום וראשי פרקים, וצ׳אט קבוצתי עם סקרים.

## מה יש במערכת

יש שלושה תפקידים:

- **מנהל מערכת** יוצר משתמשים וקורסים ומשייך מרצים וסטודנטים. אפשר לייבא סטודנטים מקובץ CSV או XLSX, כולל ייצוא משתתפים מ-Moodle כמו שהוא.
- **מרצה** עורך את התכנים בעמוד הקורס, פותח דגימות נוכחות, מעלה הקלטות ויוצר סקרים בצ׳אט.
- **סטודנט** רואה את הקורסים שלו, מסמן נוכחות, כותב בצ׳אט (גם באנונימיות) ועונה לסקרים.

ההתחברות היא עם חשבון Google, והשרת מאמת את ה-ID Token. מי שלא רשום בטבלת המשתמשים לא נכנס. לפיתוח ולדמו יש מצב `MOCK_AUTH` עם בורר תפקיד.

### נוכחות

המרצה מזין מספר שיעור ופותח דגימה. מספר חדש פותח שיעור חדש, ומספר קיים מוסיף דגימה לאותו שיעור, עד 5 דגימות לשיעור. כל דגימה פתוחה לזמן קצר (ברירת המחדל היא 2 דקות).

בזמן הדגימה המסך של המרצה מציג QR שמתחלף כל 6 שניות, ובמקביל הרמקול משמיע אות בתדר גבוה (17.2 עד 19.5 קילוהרץ) שרוב האנשים לא שומעים. גם האות מתחלף. שני הקודים נגזרים ב-HMAC מסוד השרת, ממזהה הדגימה ומחלון הזמן, ולא נשמרים ב-DB.

הסטודנט סורק את ה-QR עם המצלמה, הדף שנפתח מקשיב כמה שניות למיקרופון, מפענח את האות ושולח אותו לשרת. אם אין מיקרופון, אין הרשאה, או שהפענוח לא הצליח תוך 10 שניות, הנוכחות נרשמת בכל זאת, עם QR בלבד, ומסומנת כחשודה. אותו דבר קורה כשהכתובת מחוץ לטווחי הקמפוס. המרצה מאשר או דוחה רשומות חשודות בדוח השיעור. סטודנט אף פעם לא נחסם רק בגלל האודיו.

הדוח הוא מטריצה של סטודנט מול דגימות, עם אחוז נוכחות לכל סטודנט, וייצוא ל-CSV שנפתח נכון באקסל.

### צ׳אט וסקרים

צ׳אט אחד לכל קורס, בסגנון וואטסאפ: תגובה עם ציטוט, ו-6 אימוג׳ים קבועים שנפתחים בלחיצה ארוכה בטלפון או במעבר עכבר במחשב. כל משתמש שם reaction אחד להודעה. הודעה אנונימית מוסתרת מכולם, כולל המרצה, ורק מנהל המערכת רואה מי שלח אותה. ההסתרה נעשית בשרת, כך שגם ה-JSON שמגיע לדפדפן לא כולל את זהות השולח.

המרצה יוצר סקר מתוך הצ׳אט ובוחר במתג אם ההצבעה אנונימית. בסקר אנונימי, שהוא ברירת המחדל, כולם רואים רק כמה הצביעו לכל תשובה. בסקר גלוי כולם יכולים לראות גם מי הצביע לכל תשובה. כל סטודנט מצביע פעם אחת ויכול לשנות את הבחירה. העדכון הוא ב-polling כל 2.5 שניות.

### הקלטות

המרצה מעלה קובץ וידאו או אודיו. ברקע, ffmpeg מחלץ את האודיו, faster-whisper (מודל `small`) מתמלל על המחשב המקומי, ו-Gemini כותב סיכום, נקודות מפתח וראשי פרקים עם חותמות זמן. לחיצה על ראש פרק מקפיצה את הנגן לאותה נקודה. אם הסיכום נכשל, התמלול נשמר, ובניסיון חוזר רק הסיכום ירוץ שוב.

## מבנה הקוד

```
moodleplus/
  __init__.py        create_app: רישום blueprints, DB וטיפול בשגיאות
  schema.sql         כל הטבלאות (SQLite במצב WAL)
  services/          הלוגיקה, בלי Flask. כל מחלקה עם אחריות אחת
    users.py         UserService, StudentImporter
    courses.py       CourseService, EnrollmentService (הרשאות ברמת הקורס)
    content.py       ContentService, FileStore
    tokens.py        TokenClock, QrTokenService, AudioTokenService
    network.py       CampusNetworkPolicy
    attendance.py    AttendanceService, AttendanceReport
    chat.py          ChatService, SenderMask, ReactionService
    polls.py         PollService
    recordings.py    RecordingService, BackgroundJobRunner
    transcription.py Transcriber, WhisperTranscriber, AudioExtractor
    llm.py           LLMProvider, GeminiProvider, LessonSummarizer
  blueprints/        routes דקים: קוראים את הבקשה, קוראים ל-service ומחזירים תבנית או JSON
  static/js/         audio_emitter.js (AudioTokenEmitter), audio_listener.js (AudioTokenListener), chat.js ועוד
tests/               בדיקות pytest לכל service
seed.py              נתוני דמו
```

ה-routes לא ניגשים ל-DB ישירות. כל הלוגיקה והבדיקות נמצאות בשכבת ה-services, וזו השכבה שממנה כדאי לצייר את דיאגרמת המחלקות.

## הרצה מקומית

צריך Python 3.12 ומעלה, ו-ffmpeg בשביל ההקלטות.

```bash
python -m venv venv
venv\Scripts\activate            # ב-Mac או Linux: source venv/bin/activate
pip install -r requirements.txt
copy .env.example .env           # ב-Mac או Linux: cp
python seed.py --reset           # נתוני דמו: מרצה, 105 סטודנטים, קורס עם תכנים, צ׳אט וסקר
python run.py
```

האתר עולה בכתובת `http://localhost:5000`. כש-`MOCK_AUTH=1`, בעמוד ההתחברות בוחרים תפקיד ומשתמש. המייל של מנהל המערכת נלקח מ-`ADMIN_EMAIL`, והוא נוצר אוטומטית בהרצה הראשונה.

הגדרות חשובות ב-`.env`:

| משתנה | מה הוא עושה |
| --- | --- |
| `SECRET_KEY` | הסוד שממנו נגזרים הטוקנים וה-session. בדמו חייב להיות ארוך ואקראי |
| `MOCK_AUTH` | `1` מציג בורר תפקיד, `0` משאיר רק את Google |
| `GOOGLE_CLIENT_ID` | מ-Google Cloud Console |
| `CAMPUS_CIDRS_FILE` | קובץ טווחי ה-IP של הקמפוס, ברירת המחדל היא `data/campus_ips.txt` |
| `GEMINI_API_KEY` | מפתח חינמי מ-[Google AI Studio](https://aistudio.google.com/apikey) |
| `GEMINI_MODEL` | ברירת המחדל היא `gemini-3.8-flash` |
| `WHISPER_MODEL` | ברירת המחדל היא `small`. אפשר `base` כדי לתמלל מהר יותר |

בהעלאה הראשונה faster-whisper מוריד את המודל (בערך 460MB), ואחר כך הוא נשמר במטמון. במחשב נייד, תמלול של שיעור באורך שעה וחצי לוקח בערך 20 עד 40 דקות.

שימו לב: ב-free tier של Gemini, Google רשאית להשתמש בתוכן כדי לשפר את המודלים שלה. לכן לא כדאי להעלות הקלטות עם מידע רגיש.

## הרצה עם tunnel (בשביל טלפונים)

בטלפון, המיקרופון עובד רק ב-HTTPS. הדרך הפשוטה היא Quick Tunnel של Cloudflare, בחינם ובלי חשבון:

```bash
winget install --id Cloudflare.cloudflared     # ב-Mac: brew install cloudflared
python run.py                                  # בחלון אחד
cloudflared tunnel --url http://localhost:5000 # בחלון שני
```

cloudflared מדפיס כתובת בסגנון `https://something.trycloudflare.com`, ואותה פותחים בטלפונים. הכתובת מתחלפת בכל הפעלה. כדי שהתחברות עם Google תעבוד מאחורי ה-tunnel, צריך להוסיף את הכתובת ב-Google Cloud Console תחת Authorized JavaScript origins.

מאחורי ה-tunnel השרת רואה את כתובת ה-IP הציבורית של הטלפון, דרך הכותרת `CF-Connecting-IP`. לכן ב-`data/campus_ips.txt` צריך לכתוב את הטווחים הציבוריים של רשת הקמפוס ולא כתובות פנימיות כמו `10.x`. קובץ ריק מכבה את בדיקת ה-IP.

## בדיקה באולם לפני הדמו

1. במחשב של הכיתה פותחים `/debug/audio`, לוחצים ״השמע אות בדיקה״ ומרימים את הווליום.
2. בטלפון פותחים את אותו עמוד דרך ה-tunnel ולוחצים ״התחל להקשיב״.
3. בודקים מהשורה האחרונה שהעמודות עולות ושהקוד שפוענח זהה לקוד שבמחשב. מתחת ל-14 dB מעל הרעש הפענוח לא יעבוד, וכדאי לקרב רמקול או להגביר.

גם אם האודיו לא עובד באולם, הדמו ממשיך: הנוכחות נרשמת עם QR בלבד, והמרצה מאשר אותה בדוח.

## בדיקות

```bash
pytest -q
```

הבדיקות לא צריכות רשת או מודלים. הן משתמשות בשעון מזויף ובמימושים מדומים של התמלול וה-LLM, ומכסות בין השאר את מגבלת 5 הדגימות, את תוקף הטוקנים של ה-QR ושל האודיו, את מסלול ה-fallback, ייחודיות הצבעה, reaction אחד למשתמש, אנונימיות לפי תפקיד והרשאות.
